# 按 rayburst 架构重构多线程下载引擎

## Context（背景与目标）

当前下载引擎是 PCL2 语义的 Rust 移植，但组织混乱：

- **`net.rs`（2782 行单体）** 混杂 4 个重叠的下载入口（`download_file` / `download_file_with_mirrors` / `download_file_multithreaded` / `download_file_resumable`）、镜像链、Range 探测、分段下载、断点续传、限速平滑、Mojang manifest 逻辑和测试。
- **`download.rs`（749 行）** 的 PCL2 状态机（`NetFile`/`NetState`/`LoaderTaskView`/`format_download_failure`）是**死代码**——从未被引擎引用；实际在用的只有令牌桶、线程护栏、源分类原语。
- 19 处调用点（minecraft/loaders/java/content/bedrock/littleskin/multiplayer）签名各异；错误全部是 `Result<_, String>`；`net.rs:160` 与 `download.rs:180` 存在重复的 `is_bmclapi`。

**参考 rayburst 的架构模式**（原生引擎路线，用户已确认）：模块分层（`error.rs` 结构化错误 / `types.rs` 请求类型 / 引擎与策略分离 / 任务状态机 / 速度服务）、单一统一入口、thiserror 错误模型。**不引入 aria2 sidecar**（rayburst 实际是委托 aria2，这里保留原生 reqwest 引擎以保住 BMCLAPI 镜像链、SHA-1 校验、断点续传等启动器特有能力）。

**明确不在范围内**：aria2 集成、SQLite 下载历史库、定时限速调度、前端与 IPC payload 任何改动（`install:progress` 等事件结构保持字节级不变）。

## 新模块结构

`download.rs` 单文件 → `download/` 目录（模仿 rayburst `aria2/`+`engine/`+`services/`+`error.rs` 分层）：

```
src-tauri/src/download/
├── mod.rs       模块文档 + 公共 re-export（对外唯一门面）
├── error.rs     DownloadError（thiserror，仿 rayburst error.rs）+ classify_source_failure/should_disable_source（从 download.rs 迁入，改为按错误枚举匹配而非字符串猜测）
├── types.rs     DownloadRequest<'a>、MIN_MULTITHREAD_SIZE/NET_BUFFER_SIZE 等常量
├── source.rs    NetSource/sources_for/NetSource 健康管理（download.rs 迁入）+ get_mirror_urls/preferred_urls/rewrite_to_custom_mirror/is_bmclapi/DownloadSourceProbe/probe_download_sources（net.rs 迁入）
├── limit.rs     LimitState 令牌桶/ThreadGuard/thread_limit/record_connect/thread_timeout_ms（download.rs 迁入）
├── segments.rs  RangeProbe/probe_range_support/compute_segments/recommended_segments/parse_content_range_total/fetch_range_into（net.rs 迁入）
├── resume.rs    ResumeMeta/旁车路径/resume_progress/read/write/discard_partial（net.rs 迁入）
├── speed.rs     SpeedSmoother（net.rs 迁入）
├── verify.rs    FileChecker/sha1_file/verify_and_commit/looks_complete/part_path（download.rs + net.rs 迁入；FileChecker 错误文案保持逐字节一致）
├── task.rs      NetFile/NetState/LoadState/LoaderTaskView/format_download_failure（download.rs 迁入并激活）
├── engine.rs    统一入口 download()：吸收 4 个旧入口的全部路径（分段并行 + 失败分片低并发补抓 + 单流 + ResumeMeta 续传 + 直连→代理升级 + 镜像链轮换）
└── tests.rs     现有 net.rs 本地 HTTP 服务集成测试迁移 + 新增用例
```

`net.rs` 瘦身后只保留：HTTP 客户端（`client`/`direct_client`/`get_prefer_direct`）、`fetch_json`、`describe_error`、`proxy_retry_worthwhile`、Mojang manifest 区段。`net.rs` 中重复的 `is_bmclapi` 删除，统一走 `download::source`。

## 统一引擎 API（核心设计）

```rust
// types.rs —— 带生命周期避免调用点所有权改造（现有闭包已 move+Arc 克隆、retry_counter 是 &AtomicU64 借用）
pub struct DownloadRequest<'a> {
    pub url: String,
    pub dest: PathBuf,
    pub expected_sha1: Option<String>,
    pub expected_size: Option<u64>,
    pub threads: Option<usize>,        // None → per_file_threads(expected_size)
    pub sources: Option<Vec<String>>,  // None → preferred_urls + get_mirror_urls 自动镜像链
    pub resume: bool,                  // 启用 ResumeMeta 断点续传
    pub retry_counter: Option<&'a AtomicU64>,
    pub on_progress: Option<&'a mut (dyn FnMut(u64, u64, u64) + Send)>,
}

// engine.rs —— 唯一执行路径
pub async fn download(req: DownloadRequest<'_>) -> Result<u64, DownloadError>
```

引擎流程（取四条旧路径的并集，行为取最强者）：解析源列表 → 直连客户端逐源尝试 → 每源先 `probe_range_support`；大文件分段并行（预分配 `.part`，`resume: true` 时沿用/新建 ResumeMeta，JoinSet + mpsc 进度聚合 + 看门狗 + 429/503 退避，部分失败不丢弃已有分片、低并发补抓）→ 小文件单流（30s 停滞超时 + ≤2MB 内存缓冲 + 流式 SHA-1）→ `verify_and_commit`（FileChecker 尺寸+SHA-1）→ 直连失败且 `proxy_retry_worthwhile` 时整条源链经代理客户端重放。进度回调保持现状语义（字节精确、单调钳制包装一次在引擎内完成）。

**错误策略**：`DownloadError` 各变体 `Display` 输出保持现有错误文案逐字节一致（现有测试和调用方 `format!` 包装依赖它）；bridge.rs 边界仍是 `Result<_, String>`，调用方 `.map_err(|e| e.to_string())`。已确认**无调用方检查错误字符串内容**，迁移安全。

**状态机激活（task.rs）**：`engine.rs` 内部为每次下载维护 `NetFile` 实例——真实驱动 `NetState` 状态转移（`WaitingToCheck→Connecting→Reading→Downloading→Merging→Finished/Canceled`，判别值 -1..6 不变）与 `download_done` 记账；`LoaderTaskView` 经 `engine::task_view()` 成为 `get_download_stats` 的**可选新增字段**（camelCase，前端类型为 optional，零破坏）；多源失败报告改用 `format_download_failure`（现有 `last_error` 单串保留为 Display 兼容输出）。**不**用 PCL2 进度曲线替换现有字节级进度回调（UI 行为不变）。

## 19 处调用点迁移映射（机械替换）

| 现调用 | 新写法要点 |

## 实施步骤（分 4 个提交，每个提交保持 `cargo test` 绿）

1. **骨架迁移**：建 `download/` 目录，将上述原语从 `download.rs`/`net.rs` 平移进各子模块；`download.rs` 删除、`net.rs` 以 `pub use crate::download::…` 保持旧路径编译。纯移动零行为变化。
2. **统一引擎**：`engine.rs` 吸收 4 条下载路径为单一 `download()`；4 个旧函数暂时改为新引擎的薄包装（净删 ~600 行重复）。迁移集成测试到 `download/tests.rs`，新增镜像失效切换 / 续传往返 / retry_counter 记账用例。
3. **全量迁移**：按上表迁移 19 处调用点与辅助导入；删除旧 4 个入口函数；`net.rs` 定稿为 HTTP/manifest 门面。
4. **状态机激活**：engine 驱动 `NetFile`/`NetState` 转移，`get_download_stats` 增加可选 `active_tasks`（LoaderTaskView 视图），多源失败报告接入 `format_download_failure`。

`Cargo.toml` 新增 `thiserror = "2"`（零传递依赖）。
