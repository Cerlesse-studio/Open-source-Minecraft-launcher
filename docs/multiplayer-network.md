# 联机网络方案：纯 IPv6 P2P（默认）与公益节点模式

## 概述

启动器联机基于 [EasyTier](https://github.com/EasyTier/Easytier)。默认使用**纯 IPv6 P2P**：

- 房主和访客各有一个公网 IPv6 地址，通过分享码 + 回执码手动交换入口。
- 两端都以 `--p2p-only --need-p2p` 启动，强制只走已建立的 P2P 链路。
- 显式清空 IPv4 / IPv6 STUN 列表，不联系公共 STUN，也不连接任何共享节点。
- 连接失败时不会自动回退中继；界面会明确显示失败原因。
- 仍然可以在创建页切换到**公益节点模式**：没有公网 IPv6，或运营商/路由器禁止入站 UDP 时使用。

> IPv6 地址本身不等于可入站。家用路由器的状态防火墙可能允许打洞建立回程，也可能直接丢弃所有入站 UDP；后者无法由启动器远程修改，纯 P2P 会失败。

---

## 环境要求

房主和所有访客都要满足：

1. **公网 IPv6**：`2000::/3` 全球单播地址，不是 `fe80::`、`fd00::` 等本地地址。
2. **EasyTier ≥ 2.3.0**：IPv6 打洞从该版本开始可用；启动器内置版本为 `v2.6.4`。
3. **本机放行**：允许 `easytier-core` 使用 UDP/TCP 监听端口（默认 `11010`）。安装版会写入本机规则，便携版需要系统防火墙允许该程序。
4. **路由器**：通常不需要端口映射；但若路由器 IPv6 防火墙直接丢弃入站 UDP，需要在路由器放行 UDP `11010`，或改用公益节点模式。
5. 暂时关闭可能篡改 UDP/STUN 行为的代理、加速器或安全软件。

## 联机流程

### 1. 房主创建房间

1. 在游戏里进入单人存档，按 `ESC` → **对局域网开放**；启动器会从本次日志自动读取端口。
2. 打开「联机 → 创建房间」，连接方式选择 **纯 IPv6 P2P**。
3. 选择一个稳定的公网 IPv6 地址，确认 EasyTier 监听端口（默认 `11010`）。
4. 点击 **立即创建房间**，然后把「一键分享码」发给好友。

分享码形如：

```text
cobble-mp://join?name=...&secret=...&mode=p2p&peer=udp%3A%2F%2F%5B240e...%5D%3A11010&ip=10.126.126.1&port=25565&lp=11010
```

### 2. 访客加入

1. 访客在「加入房间 → 一键分享码」粘贴房主的分享码。
2. 点击加入后，访客内核先启动；此时房主还看不到访客，属于正常现象。
3. 访客在房间页的「纯 IPv6 P2P」面板复制**回执码**发给房主。
4. 房主粘贴回执码并点 **登记**。房主内核通过本机 RPC 向访客 IPv6 入口发起直连，不会重启。
5. 双方成员列表出现对方、链路显示 `p2p` / `udp6` 后，游戏内即可通过局域网列表或 `127.0.0.1` 桥接端口进入。

回执码形如：

```text
cobble-mp://reply?name=...&peer=udp%3A%2F%2F%5B240e...%5D%3A11010
```

回执码只包含访客的 IPv6 入口和房间名，不包含房间密码。

## EasyTier 参数

纯 P2P 房主与访客都会使用：

```text
--p2p-only true
--need-p2p true
--listeners udp://[::]:11010,tcp://[::]:11010
--stun-servers ""
--stun-servers-v6 ""
```

- `--p2p-only`：未建立直连的节点流量直接丢弃，不经过中继。
- `--need-p2p`：向对端声明需要主动建立 P2P。
- `--stun-servers ""` / `--stun-servers-v6 ""`：覆盖 EasyTier 内置 STUN 默认值，确认不向第三方查询映射。
- 房主没有 seed 节点也能启动监听；不回落到 `public.easytier.cn`。

---

## 公益节点模式

创建页切换到「公益节点模式」后：

- 双方通过 EasyTier 共享节点协助打洞，失败时允许中继转发。
- 房主以 `--no-listener` 启动，不开放本机入站端口，不需要路由器映射。
- 这是可选路径，不会在纯 P2P 失败时自动切换。

---

## 排障

1. **创建按钮灰色**：检查本机是否有公网 IPv6、是否选择了地址、监听端口是否有效、EasyTier 是否 ≥ 2.3.0。
2. **访客一直等待**：确认房主已经登记回执码，且双方监听端口一致；成员列表没有对方说明打洞未建立。
3. **成员列表有对方但游戏连不上**：确认房主已「对局域网开放」、端口一致；访客使用房间页给出的 `127.0.0.1:端口`。
4. **视频/日志显示 `relay`**：当前不是纯 P2P 链路，检查是否误切回公益节点模式或旧配置残留。
5. **路由器直接丢包**：纯 P2P 无法在这种环境下成功；在路由器放行 UDP，或改用公益节点模式。

---

## 隐私

- 纯 P2P 模式下，游戏流量只经过房主和访客两台电脑。
- 房间密码用于 EasyTier 网络认证和传输加密；回执码不含密码。
- 启动器不存储房间信息，也不提供中央信令服务。
