01概览

Open-source-Minecraft-launcher 是一个基于 Tauri 2 的桌面 Minecraft 启动器：前端使用 React 19 + TypeScript，后端使用 Rust 2024。界面通过 Tauri Command 调用后端能力，下载、解包、校验、启动与 EasyTier 进程都由 Rust 持有。

项目主要面向 Windows 10 / 11 做完整适配；Java 版核心保持跨平台，可在 macOS / Linux 尝试构建运行，基岩版与 Xbox 运行时相关能力目前仅限 Windows。

双版本Java 版与基岩版共用一套版本库与启动入口。
原生后端下载、安装、启动、账户、联机都在 Rust 侧完成。
本地优先账户令牌、下载断点与游戏数据默认保存在本机。
可替换内容源、下载源、Java、主题与主页都可以自行配置。

技术栈

层级技术职责
桌面容器Tauri 2原生窗口、进程管理、IPC、打包
前端React 19 · TypeScript · Vite页面、状态与交互
UITailwind CSS 4 · Radix UI · Lucide · Sonner样式、组件原语、图标、通知
后端Rust 2024 · tokio · reqwest · serde下载、安装、启动、账户、联机
存储本地文件系统 + JSON版本、配置、账户、存档与缓存

02环境要求

运行预编译版本与从源码构建的要求不同。预编译版本主要需要系统 WebView 与网络；源码构建还需要 Node.js、Rust 与 Tauri 的系统依赖。

项目要求
操作系统Windows 10 / 11 x64（推荐，功能完整）；macOS / Linux 可尝试构建运行 Java 版
Node.js20.19+ 或 22.12+
Ruststable，1.85+（项目使用 edition 2024）
Tauri 2 系统依赖Windows WebView2；macOS Xcode Command Line Tools；Linux 的 WebKitGTK 等依赖，见 Tauri 前置条件
网络首次安装版本、依赖和 Java 需要联网
其他基岩版需要 Windows 10 / 11；联机需要公网 IPv6

平台说明Windows 是完整功能平台；macOS / Linux 目前以 Java 版构建运行为主，基岩版、Xbox 运行时、winget 与 Windows 防火墙集成不可用。

03快速开始

从源码运行开发版，或者直接构建安装包。

bash
git clone https://github.com/Cerlesse-studio/Open-source-Minecraft-launcher.git
cd Open-source-Minecraft-launcher
npm install
npm run tauri dev

Windows PowerShell如果提示「无法加载 npm.ps1，因为在此系统上禁止运行脚本」，改用 npm.cmd run tauri dev，或在 cmd 中执行 npm run tauri dev。

构建安装包

bash
npm run tauri build

构建产物输出在 src-tauri/target/release/bundle/。首次构建需要编译全部 Rust 依赖，会比日常开发慢很多。

测试

bash
# 前端类型检查 + 生产构建
npm run build

# Rust 单元测试
cargo test --manifest-path src-tauri/Cargo.toml

04架构设计

整体分为四层：React 前端负责呈现，Tauri IPC 负责通信，Rust 后端负责所有耗时与关键状态，外部服务提供版本、内容、账户与联机能力。

FRONTEND React 19 + TypeScript

页面、设置、主题、PCL2 主页、IPC 桥接

→
BRIDGE Tauri 2 IPC

Command 调用 · Event 推送 · 窗口与进程

→
BACKEND Rust 2024

版本、下载、账户、基岩版、EasyTier

外部服务：Mojang / BMCLAPI / Betacraft · Modrinth / CurseForge / MC百科 · Microsoft / Xbox Live · EasyTier

设计取舍

  • 后端持有状态：安装与下载任务挂在 Rust 侧，切换页面不会中断；前端重新进入页面时读回真实进度。
  • 原子写入：下载先写 .part，校验 SHA-1 后再提交到目标路径；失败不会留下半成品文件。
  • 下载源透明：镜像失败会自动回退，用户不需要知道每个文件来自哪个源。
  • 账户令牌不经过前端：启动时会话由后端账户存储直接读取，减少令牌在 UI 层暴露的机会。

05下载引擎

下载引擎是启动器最核心的基础设施。版本核心、依赖、资源文件、模组、资源包与 EasyTier 内核都走同一套下载流程。

分片与自适应

文件 ≥ 1 MB 时按 HTTP Range 分片，每片至少 512 KB；线程档位 1–64 可调，分片并发实际上限 16 路。单文件小于 1 MB 仍走单线程。

场景处理方式
分片启动后 12 秒内低速不判失败，给镜像爬坡时间
12 秒后总吞吐持续 < 8 KB/s放弃分片，改用单连接继续下载
单个分片 30 秒收不到字节判定连接失效，重试或回退
镜像返回 429 / 503退避后逐个补齐剩余分片，避免整体失败
文件 < 1 MB直接单线程
分片 < 512 KB合并分片，避免过度切分

镜像容灾

候选地址覆盖官方 / 亚太 Anycast CDN、BMCLAPI、Forge / NeoForge / Fabric / Quilt Maven、Betacraft 旧版本资源、GitHub 加速镜像与 10 个 Xbox Live CDN 主机。遇到 404、超时或连接失败会自动换源；自定义镜像按 BMCLAPI 兼容路径重写，并校验必须为 http(s) 地址。

断点续传

任务通过 .part.meta 记录分片布局与完成情况，.part 不会在失败或换镜像时被删除。已下好的分片不会重复拉取；只有旁车文件与 .part 对不上时才自动重来。

为什么默认不是 64 线程？镜像对高并发连接很敏感。启动器会把实际分片并发限制在 16 路，并在吞吐过低时退回单连接，通常比盲目拉满线程更稳。

06账户体系

启动器同时支持微软账户与离线账户。微软登录采用 OAuth 2.0 设备码流程，不收集密码。

微软登录链路

  1. 向微软申请设备码，在浏览器中完成登录。
  2. 轮询令牌端点，拿到 Microsoft access token。
  3. 通过 Xbox Live 用户认证与 XSTS 授权。
  4. 调用 Minecraft Services 登录，获取 Java 会话。
  5. 读取 profile 与 entitlements，确认 Java / 基岩版授权。

刷新令牌保存在应用配置目录的 account.json；启动时由后端直接读取，不经过前端传输。Unix 平台会把文件权限设置为 0600。登录窗口只允许打开微软 / Xbox 官方域名。

离线账户

离线账户使用昵称与确定性 UUID，支持随机、Steve、Alex、Mojang 正版皮肤与本地自定义皮肤。自定义皮肤会打成 OfflineSkinPack 并写入 options.txt 的 resourcePacks；Mojang 皮肤通过官方签名纹理注入，1.19.2 及更早版本离线进入也能显示。

不要分享账户文件account.json 包含刷新令牌。提交 Issue 或分享日志时，请不要粘贴账户文件或任何令牌内容。

07联机

联机以内置的 EasyTier v2.6.4 为内核，用公网 IPv6 做点对点直连，不依赖中转服务器。

三步开房

  1. 装内核：双方进入「联机」页安装 EasyTier 内核。任务由后端持有，切页、重启启动器都可继续下载。
  2. 创建房间：房主选择本机的公网 IPv6 作为入口；进入游戏后点「对局域网开放」，启动器会从本次 logs/latest.log 自动读取端口并生成分享码。
  3. 加入房间：好友粘贴整段分享码加入，打开游戏「多人游戏 → 局域网」即可看到世界；也可以手动直连房间页给出的 10.126.126.x:端口。

分享码与局域网发现

分享码格式为 cobble-mp://join?name=…&secret=…&peer=…&ip=…&port=…，把网络标识、密钥、房主入口地址、虚拟地址和世界端口打包成一段文本。房主监听 tcp://[::]:11010 / udp://[::]:11010，访客把房主公网 IPv6 作为初始对等节点。

点「显示到局域网」后，后端会在 127.0.0.1 上开一个 TCP 代理，并持续向 224.0.2.60:4445 与 127.0.0.1:4445 发送 [MOTD]…[/MOTD][AD]…[/AD]，好友的世界会直接出现在「多人游戏 → 局域网」里。

公网 IPv6 是硬性条件当前设计不内置中转节点。双方都需要可用的公网 IPv6；房主还需要放行 TCP / UDP 11010 与 Minecraft 世界端口，路由器 / 光猫一侧要自行做对应放行。

08基岩版

基岩版模块面向 Windows 10 / 11，支持商店客户端、.msixvc GDK 加密包、UWP / AppX 与 BDS 独立核心。

核心与依赖

所有基岩版启动路径都会在启动前自检运行依赖；Xbox GDK 路径会通过 winget 自动补齐「Xbox 应用」与「游戏服务」。UWP / AppX 核心由启动器自行解包，并以开发模式注册，不经过 Microsoft Store。

集成 90+ 条官方 Xbox Live CDN 直链，覆盖正式版与预览版；BDS 版本源可在 EndstoneMC、MCServerJars 与 Azure CDN 镜像之间切换。

附加包与存档

原生支持 .mcpack / .mcaddon / .mcworld。安装时读取包内 manifest.json，按模块类型分区解压；.mcaddon 内嵌的 .mcpack 会递归安装，.mcworld 通过 level.dat 识别并导入 minecraftWorlds。安装结果会写入所有已存在的游戏数据目录。

附加包管理器会扫描所有已存在的 com.mojang 数据目录，按资源包、行为包、皮肤包、世界模板分组，支持启停、批量操作、删除与本地导入。停用会把包移动到同目录的 cobble_disabled_packs。

加载器与 DLL 模组

  • LeviLamina：接入官方 levilamina-client-version-db，匹配并部署对应版本。
  • Amethyst：原生 C++ 客户端 Mod 注入框架。
  • DllMods：支持原生 .dll 模组、LeviLamina 插件与行为包的一键启停（.disabled 切换）、删除与本地导入。

10数据目录

默认游戏目录为 ~/.cobble（Windows 下通常是 C:\Users\<用户名>\.cobble），可以在设置中修改。

text
~/.cobble/
├── assets/                  # 游戏资源（音效、语言、贴图）
├── libraries/               # Java 依赖库
├── meta/                    # 版本清单缓存
├── versions/                # 各版本核心与实例
│   └── <版本或实例>/
│       ├── mods/
│       ├── resourcepacks/
│       ├── saves/
│       └── logs/
├── saves/                   # 未启用版本隔离时的共享存档
├── resourcepacks/           # 共享资源包
├── shaderpacks/
├── datapacks/
├── modpacks/                # 从内容市场下载的整合包
├── runtime/                 # 自动下载的 Temurin JRE
│   └── temurin-<major>/
├── easytier/                # EasyTier 内核、安装状态与断点
└── bedrock/
    ├── versions/            # UWP / AppX / BDS 核心
    ├── games/com.mojang/    # 便携数据目录
    └── cache/               # 基岩版下载缓存

账户文件不在游戏目录里，而是位于应用配置目录（Windows 通常为 %APPDATA%\com.opensource.minecraft.launcher\account.json），因此切换游戏目录不会退出登录。

备份建议复制整个游戏目录即可备份存档、模组、资源包与游戏内配置；启动器设置与账户在应用自己的数据目录，建议单独备份 account.json。

11构建与测试

日常开发、构建与测试命令如下。提交 PR 前建议至少运行前端构建与 Rust 测试。

bash
# 前端类型检查 + 生产构建
npm run build

# Rust 单测
cargo test --manifest-path src-tauri/Cargo.toml

# 可选的下载 / 启动冒烟测试（会真实下载并尝试启动游戏）
cargo run --manifest-path src-tauri/Cargo.toml --example smoke -- 1.8.9

安装包由 npm run tauri build 生成，产物位于 src-tauri/target/release/bundle/。首次构建会编译全部 Rust 依赖，耗时会明显更长。

格式化cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
静态检查cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings

12常见问题

需要正版账号吗？

不强制。离线账户可以启动单人与离线服务器；微软账户登录后可获得正版 Java 会话、皮肤与基岩版授权检测。启动器不会要求输入微软密码，登录在微软官方页面完成。

没有安装 Java，或者 Java 版本不匹配怎么办？

启动器会按版本元数据匹配 Java 主版本；找不到时自动下载 Temurin JRE 到 <游戏目录>/runtime/。也可以在「设置 → 游戏与启动」或版本设置里手动指定 Java。

基岩版一定要安装 Microsoft Store 吗？

不必须。启动器支持 UWP / AppX 以开发模式注册、.msixvc GDK 核心与 BDS 独立核心；商店客户端只是其中一种来源。GDK 路径会通过 winget 补齐 Xbox 应用与游戏服务。

联机需要公网 IPv6 吗？

是。当前设计是公网 IPv6 点对点直连，不内置中转节点。双方都需要可用的公网 IPv6；房主还需要放行 TCP / UDP 11010 与 Minecraft 世界端口。

下载慢、镜像 404 或经常中断怎么办？

先在「设置 → 下载与网络」里测速并切换到更快的源，线程数建议 8–16。镜像对高并发限速时，启动器会自动退回单连接；大文件支持断点续传。遇到 404 会自动尝试备用镜像。

启动失败怎么排查？

先看主页 / 版本设置里的实时日志，确认 Java 主版本、游戏目录权限、版本隔离与模组冲突；旧版本注意 LegacyFix 相关参数。仍然无法解决时，请附上日志、系统信息和复现步骤提 Issue，不要粘贴账户令牌。
